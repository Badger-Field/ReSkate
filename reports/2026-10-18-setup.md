- **First attempt (default VS 2022 generator, `cmake --build --preset release --parallel`): failed.**
  Not a code failure — file-lock / permission contention under heavy MSBuild parallelism:
  - `EmotePacker\main.cpp(1,1): error C1083: Cannot open compiler generated file: '...main.obj': Permission denied`
  - `dingosdk_thunderstore_tests.vcxproj: cl : command line error D8040: error creating or communicating with child process`
  - `Engine\Vfs\initfs.cpp(1,1): error C1041: cannot open program database '...dingosdk_initfs.pdb'; if multiple CL.EXE write to the same .PDB file, please use /FS`
  - Windows Defender real-time + behavior + on-access scanning are all ON, which commonly causes
    this when many `cl.exe` write objects/exes at once. No security setting was changed or bypassed.
- **Second attempt (`ci\local.ps1 -Ninja`, build dir `build/ninja-x64`): succeeded.** 621 compile
  steps, exit 0, "Windows checks passed." Ninja uses one coherent build instead of ~57 MSBuild
  worker nodes, which avoids the PDB/child-process contention. Recommend the Ninja preset as the
  default on this machine.
